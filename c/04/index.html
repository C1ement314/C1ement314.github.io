4.3 进阶篇：再懂原理

基础篇让你会写算式和条件了。进阶篇要讲清楚：为什么有些表达式会先算乘法，为什么逻辑运算有时会“偷懒”，以及整数计算为什么会溢出。

4.3.1 运算符优先级

当一个表达式里有多个运算符时，C 语言需要决定先算哪一个，这就是优先级。

一个简化的优先级顺序如下，从高到低：

优先级 运算符 说明
高 () 括号
!、++、--、一元 +、一元 - 一元运算
*、/、% 乘、除、取余
+、- 加、减
<、<=、>、>= 关系比较
==、!= 相等比较
&& 逻辑与
|| 逻辑或
?: 条件运算
低 =、+=、-=、*=、/=、%= 赋值

不用死记整张表。先记住几个最常见的：

  1. 括号优先级最高；
  2. *、/、% 高于 +、-；
  3. 关系比较高于 ==、!=；
  4. && 高于 ||；
  5. 赋值运算符优先级很低。

4.3.3 短路求值

&& 和 || 有一个很重要的特性：短路求值。

逻辑与 &&

如果左边已经为假，右边就不会再计算。

因为 && 的左边是 count != 0：

  • 如果 count 等于 0，左边为假，右边的 100 / count 根本不会执行，所以不会除以 0；
  • 如果 count 不等于 0，才会继续判断右边。

逻辑或 ||

如果左边已经为真，右边就不会再计算。

如果 score < 0 已经为真，后面的 score > 100 就不需要再判断了。

短路求值很有用，但也可能带来意外的“副作用不执行”问题。比如：

所以，不要把“必须执行的操作”放在短路表达式的右边。

另外要注意：

  • && 和 || 有短路求值；
  • & 和 | 是位运算，没有短路行为，两边都会求值；
  • 不要把 &、| 当成逻辑运算符来用。

4.3.6 整数溢出

每种整数类型都有范围。

如果计算结果超出了范围，就可能发生溢出：

  • 无符号整数溢出会按模运算“绕回去”；
  • 有符号整数溢出是未定义行为，不要依赖它产生任何固定结果。

例如，在常见的 32 位 int 平台上，int 的最大值通常是 2147483647。如果再加 1，就可能溢出。

写程序时，要根据数据范围选择类型。如果 int 不够大，可以考虑：

  • unsigned int
  • long
  • long long

具体范围可以包含 <limits.h> 查看，例如：

不要假设 int 一定是 32 位，也不要在溢出边缘“试探”程序的行为。

未定义行为是什么意思？

“未定义行为”不是“结果一定是某个固定值”，而是 C 标准没有规定会发生什么。

有符号整数溢出就是典型的未定义行为。编译器可能：

  • 得到某个看似正常但错误的结果；
  • 直接优化掉相关代码；
  • 程序崩溃；
  • 在不同平台、不同优化级别下表现不同。

所以，不要写依赖未定义行为的代码。更稳妥的做法是提前判断范围，或者使用更宽的类型。

4.7 总结与自测

一句话总结

算术运算符负责计算，关系运算符负责比较，逻辑运算符负责组合条件，自增自减负责改变变量；写复杂表达式时，优先加括号，别让优先级和结合性变成陷阱。
