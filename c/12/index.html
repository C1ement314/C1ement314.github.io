12.3.1 结构体的内存布局

结构体成员通常按声明顺序存放，但编译器可能会插入“填充字节”，也叫内存对齐。

结论：

  • 结构体大小不一定等于成员大小之和；
  • 成员顺序可能影响结构体大小；
  • 不要假设结构体的精确布局；
  • 用 sizeof 获取结构体大小；
  • 跨平台传输结构体时，要特别小心对齐和字节序问题。

如果想查看某个成员在结构体中的偏移，可以使用 <stddef.h> 中的 offsetof，但初学阶段先了解即可。

12.3.2 结构体传值 vs 传地址

对比项 传值 传地址
参数写法 struct Student s struct Student *s
传递内容 整个结构体的副本 结构体的地址
能否修改调用者 不能 能
复制成本 结构体越大，成本越高 只复制一个地址
成员访问 s.score s->score
只读写法 const struct Student s const struct Student *s

一般建议：

  • 小结构体可以传值；
  • 大结构体或需要修改时，传地址；
  • 只读时传 const struct Student *；
  • 需要修改时传 struct Student *。

12.3.7 union 预览（了解即可）

union 的成员共享同一块内存。

特点：

  • 所有成员从同一地址开始；
  • 大小通常等于最大成员的大小；
  • 同一时间通常只使用一个成员；
  • 读取最近写入的那个成员才比较可靠。

union 常用于特殊的数据表示、协议解析等场景。初学阶段先了解即可。

12.3.8 本章代码规范：类型名、成员名统一风格

这一章最重要的两条规范是：

  1. 类型名统一

    • 本教程使用 Student、Point、Book；
    • 也可以用 student_t、point_t，但同一个项目要统一。

  2. 成员名统一

    • 成员名使用小写加下划线，例如 student_id、book_title；
    • 成员名要能表示含义；
    • 不要用 a、b、x1 这种含混的名字。

其他建议：

  • 结构体定义后别忘了分号；
  • 值访问用 .，指针访问用 ->；
  • 字符串成员不能直接赋值，要用 strcpy 或 snprintf；
  • 不要直接用 == 比较整个结构体；
  • 结构体较大或需要修改时，优先传地址；
  • 只读时使用 const struct Student *；
  • 不要依赖结构体内部填充字节；
  • 状态和选项优先使用 enum；
  • 自引用结构必须使用指针成员。
