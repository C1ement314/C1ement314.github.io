0.1 先导：不会编程，完全没关系

如果你现在对“程序”“代码”“编译”这些词完全没有概念，那太正常了。本教程就是为零基础读者写的。

你不需要提前通过英语四级，不需要数学特别好，也不需要一上来就懂电脑的所有原理。你只需要：

  • 会打字；
  • 愿意动手试一试；
  • 遇到报错先别慌，咱们一起读错误信息。

编程不是“背咒语”，更像是学习一种表达方式：你把想法拆成一步一步的指令，然后让计算机照着执行。

0.2 基础篇：先会用

0.2.1 程序到底是什么？

先来一个很朴素的解释：

程序 = 一组有顺序的指令 + 数据。

计算机本身不会“自己想”，它只会按你写的指令做事。程序就是你对它下的命令清单。

几乎所有程序都可以看成这样一个过程：

比如一个计算器：

  • 输入：你按下 3 + 5；
  • 处理：程序计算结果；
  • 输出：屏幕上显示 8。

再比如一个闹钟：

  • 输入：你设置时间；
  • 处理：程序一直检查当前时间；
  • 输出：到点了就响。

你看，编程并不神秘，它就是把“你想让电脑做的事”拆成清晰的步骤。

0.2.2 C 语言是什么？

C 语言是一门通用的、面向过程的编程语言。

它大约在 1972 年由 丹尼斯·里奇（Dennis Ritchie） 在贝尔实验室开发，最初与 UNIX 操作系统的开发关系密切。

C 语言有几个很适合初学者的特点：

  • 接近底层：能让你理解计算机内存、数据表示等基础概念。
  • 效率高：很多操作系统、编译器、数据库和嵌入式设备都会用到 C。
  • 可移植性好：标准 C 代码通常可以在 Windows、macOS、Linux 等不同平台上编译运行。
  • 标准库实用：输入输出、字符串、内存管理等都有标准库支持。
  • 影响深远：C++、Java、C#、Go、Rust 等很多语言都或多或少受到 C 的影响。

本教程以 C11 标准为基准。C23 是较新的标准，但入门阶段不用追新，C11 已经足够学习核心知识，而且编译器支持广泛。

更准确地说：掌握 C 语言之后，你会更容易理解其他编程语言和项目中的底层概念，但仍然需要针对具体语言和项目继续学习。

0.2.3 通用 C 语言开发流程

这一段是本章最重要的内容。

不管你用的是 CLion、Visual Studio、VS Code，还是直接在命令行里敲命令，写 C 程序都有一个大致的通用流程。咱们把它拆成八步。

C 语言的源代码文件通常以 .c 结尾，例如：

第 3 步：写代码

一开始不要追求“功能完整”。先把程序写成最小可运行版本：

  • 能编译；
  • 能运行；
  • 能输出一点东西。

然后再一点一点加功能。每加一小步，就重新运行一次。这样出错时，你很容易知道是哪一步引入的问题。

编程的过程和拼积木一样，一步一个脚印。

第 4 步：编译

编译器会检查你的源代码，并把它翻译成计算机能理解的形式。

这一步常见的结果有三种：

  • 通过：没有错误，可以继续；
  • 有警告(WARNING)：程序可能仍能生成，但某些写法有风险；
  • 有错误(ERROR)：编译失败，必须先修好。

初学阶段一定要记住：警告不是装饰品，不要学习某些程序员的“能跑就是没问题”的思想。

第 5 步：链接

编译通过之后，程序还不一定能直接运行，还需要“链接”。

当你有多个代码文件和多个运行库的时候，需要通过链接将所有的东西融合到一起，才会生成最后所使用的可执行文件

链接器会把你的目标文件、标准库和其他必要的部分拼在一起，最终形成可执行文件。

所以：

编译通过 ≠ 一定能链接成功。

第 6 步：运行

终于可以运行了！

运行的时候，不要只看“有没有输出”，还要检查：

  • 输出对不对？
  • 输入不同数据时，结果还对吗？
  • 边界情况会怎样？比如输入 0、负数、很大的数、空字符串等。

第 7 步：调试和修改

程序出错太正常了，不是“你不行”，而是编程本来就是一个不断修正的过程。

遇到问题时，可以按这个顺序处理：

  1. 读错误信息；
  2. 找到错误信息里提到的文件名和行号；
  3. 看看那一行附近在做什么；
  4. 改一点，重新编译，重新运行；
  5. 如果还没解决，就缩小范围，继续定位。

0.2.4 为什么不绑定具体平台？

因为编程语言和开发工具不是一回事。

  • C 语言是编程语言；
  • 编译器负责翻译 C 代码；
  • 编辑器负责写代码；
  • IDE 把编辑、编译、调试等工具整合在一起；
  • 构建系统负责管理编译和链接的命令。

不同操作系统、不同 IDE，按钮长得不一样，但核心流程是一样的：

写代码 → 编译 → 链接 → 运行 → 调试。

本教程默认用 CLion 作为演示环境，但正文不会依赖 CLion 的专属功能。代码示例以标准 C 为主，尽量保证多平台可用。

CLion 的下载、安装和基础操作，本教程不重复；你可以参考七平的 CLion 教程。

以后写代码一定会遇到问题。提问的方式越清楚，别人越容易帮你。

  1. 读一遍错误信息；
  2. 把出错的代码缩短到最小；
  3. 自己先猜一下“哪一行、哪个变量、哪个条件可能不对”。

0.3 进阶篇：再懂原理

基础篇让你知道“大概怎么走”。进阶篇要把路面下面的结构也讲清楚。

0.3.1 从源代码到可执行文件

你写的 .c 文件叫源代码。源代码不能直接由 CPU 执行，它需要经过一系列翻译步骤。

日常口语里，我们常把整个过程统称为“编译”。但严格来说，从源代码到可执行文件，通常会经历四个阶段：

预处理

预处理器会处理以 # 开头的指令，例如：

  • #include：把头文件内容包含进来；
  • #define：进行宏替换；
  • 条件编译等。

预处理阶段主要做“文本级别的准备”，还不是真正的机器代码翻译。

编译

狭义的“编译”指把预处理后的 C 代码翻译成汇编代码。

编译器会做语法检查、类型检查、部分优化等工作。你常见的“语法错误”“类型不匹配”通常会在这一阶段被发现。

汇编

汇编器把汇编代码翻译成目标文件。

目标文件里已经是机器相关的代码，但还不是完整程序，通常不能直接双击运行。

常见的扩展名：

  • Linux / macOS：.o
  • Windows：.obj

链接

链接器把目标文件和标准库、其他目标文件连接起来，解决函数和变量的地址问题，最终生成可执行文件。

比如你调用了 printf，它的实现在标准库里。链接器负责把“调用 printf 的地方”和“printf 的实际实现”接起来。

这就解释了一个常见现象：

代码语法没问题，编译也通过了，但链接时报错：找不到某个函数。

这通常不是语法错误，而是链接阶段缺少实现或配置。

0.3.3 编译错误、链接错误、运行时错误

初学者最容易把这三类问题混为一谈。其实它们发生在不同阶段。

1. 编译错误

发生在编译阶段，通常是：

  • 少了分号；
  • 括号不匹配；
  • 变量名写错；
  • 类型不匹配；
  • 使用了未声明的函数或变量。

特点：程序无法生成可执行文件。

2. 链接错误

发生在链接阶段，通常是：

  • 声明了函数，但没有写函数定义；
  • 多个文件重复定义同一个函数；
  • 缺少某个库。

特点：编译能过，但最终生成可执行文件失败。

3. 运行时错误

发生在程序运行阶段，例如：

  • 整数除以零；
  • 数组越界；
  • 使用了空指针；
  • 读取了不存在的文件；
  • 内存泄漏。

特点：程序能启动，但可能崩溃、输出错误结果或行为异常。

4. 警告

警告不是错误，但它往往意味着代码存在潜在风险。

例如：把 double 类型的值赋给 int 变量，可能丢失小数部分。编译器可能只给个警告，程序照样能跑，但结果未必是你想要的。

不要养成“能跑就行、警告不管”的习惯。

0.3.5 Debug 和 Release

构建程序时，常见两种模式：

模式 特点 用途
Debug 保留调试信息，优化较少，方便定位问题 学习和开发阶段
Release 开启优化，程序可能更快、更小，但不易调试 发布和最终交付

初学者建议先用 Debug 模式，因为调试体验更友好。

有时候同一个程序，Debug 模式跑得好好的，Release 模式却出现奇怪问题。这通常说明代码里有未定义行为或隐含 bug，而不是“电脑在针对你”。

0.3.6 为什么现在就要有代码规范意识？

这一章不展开全部规范，但你必须先建立一个意识：

代码首先是写给人看的，其次才是给机器执行的。

计算机不在乎你叫 a 还是 student_score，但你的老师，你的同学，你的同事和未来的你在乎。

请不要让自己写的代码放一周再回来看就看不懂了！

好的代码规范能帮你：

  • 少写错；
  • 更容易发现自己写错；
  • 更容易看懂别人写的代码；
  • 以后和别人合作时不被嫌弃；
  • 项目变大时还能维护。

本教程会在前面几章顺手提醒一点小习惯，然后在第 8 章集中讲代码规范。现在你只要记住两条：

  1. 名字要尽量有意义；
  2. 认真读错误信息。

0.6 常见错误

错误 1：把 IDE 当成 C 语言

CLion 是 IDE，不是编程语言。换一个编辑器或 IDE，C 语言本身不会变。

错误 2：以为编译通过就万事大吉

编译通过只说明语法和类型检查大体上没问题，不代表逻辑正确，也不代表运行时不会崩溃。

错误 3：忽略警告

警告常常是未来 bug 的预告。初学阶段就应该养成处理警告的习惯。

错误 4：一上来就写大项目

程序越大，错误越难找。正确做法是：先写最小可运行版本，再逐步添加功能。

错误 5：卡住时只盯着代码发呆

遇到错误，先读错误信息。错误信息通常会告诉你：

  • 哪个文件；
  • 哪一行；
  • 大概是什么问题。

0.7 总结与自测

一句话总结

C 程序的通用流程是：构思 → 写代码 → 编译 → 链接 → 运行 → 调试 → 重复迭代；基础篇让你先会用，进阶篇让你懂原理。

  4. 编译错误、链接错误、运行时错误有什么区别？
  5. 基础篇和进阶篇分别应该怎么读？
  6. 为什么说“编译通过不等于程序正确”？
点击查看参考答案
  1. 程序是一组有顺序的指令和数据，用来让计算机完成特定任务。
  2. 通用、面向过程、接近底层、效率较高、可移植性较好、标准库实用、影响深远。
  3. 预处理 → 编译 → 汇编 → 链接。
  4. 编译错误发生在翻译阶段；链接错误发生在目标文件和库连接阶段；运行时错误发生在程序执行阶段。
  5. 基础篇第一次必读，先把程序跑起来；进阶篇第一遍可快速浏览，第二遍精读原理、边界和常见坑。
  6. 编译只检查语法和类型等层面；程序逻辑是否正确、运行时是否会越界或崩溃，还需要测试和调试。
