第 5 章：分支结构

阅读提示

基础篇先让你学会“根据条件走不同的路”。进阶篇会讲条件表达式的细节、分支覆盖、边界测试和防御性编程，建议第二遍精读。

我是七平。上一章，程序已经会计算和判断了。

但只会算还不够。真正有用的程序，还要能根据不同的情况，做出不同的选择。

比如学生管理系统：

  • 成绩大于等于 60 分，显示“及格”；
  • 成绩小于 60 分，显示“不及格”；
  • 90 分以上是 A，80 分以上是 B；
  • 用户选择 1，就添加学生；选择 2，就删除学生。

这些“如果……就……，否则……”的逻辑，就是分支结构。

5.1 先导：程序要学会选择

生活中充满了选择：

  • 如果下雨，就带伞；
  • 如果红灯，就停下；
  • 如果成绩达到要求，就录取。

程序也是一样。

分支结构的作用，就是让程序根据条件的真假，执行不同的代码。

C 语言中常用的分支工具包括：

  • if 语句；
  • if ... else 语句；
  • else if 多分支；
  • switch 语句；
  • 条件运算符 ?:。

本章会重点讲 if 系列和 switch，条件运算符放在进阶篇。

简单记：

  • 判断范围，例如 score >= 90，用 if；

5.3.4 防御性编程

防御性编程的核心思想是：

不要假设用户一定会输入正确的内容，也不要假设数据一定合法。

例如，成绩应该在 0 到 100 之间。如果用户输入了 -10 或 200，程序应该拒绝，而不是继续计算等级。

把这段检查放在计算之前。

防御性编程常见做法：

  1. 先检查输入是否合法；
  2. 检查除数是否为 0；
  3. 检查数组下标是否越界；
  4. 对 switch 设置 default；
  5. 对文件读取、内存申请等可能失败的操作检查返回值；
  6. 错误发生时，给出清楚提示并安全退出。

在第 3 章，咱们已经学过检查 scanf 的返回值。这就是防御性编程的一部分。

5.3.7 本章代码规范：条件可读，避免过深嵌套

这一章最重要的两条规范是：

  1. 条件要可读

    • 复杂条件加括号；
    • 避免写成一长串没有换行的逻辑；
    • 不要把 = 和 == 写混。

  2. 避免过深嵌套

    • 嵌套尽量控制在 2 到 3 层；
    • 可以用提前返回减少嵌套；
    • 复杂逻辑可以拆成小函数。

其他小习惯：

  • if、else、else if、switch、case 都使用统一缩进；
  • 即使分支里只有一条语句，也建议使用花括号；
  • 每个 case 通常写 break;；
  • switch 通常写 default；
  • 条件判断尽量从简单、明确的写起；
  • 不要写 if (x = 0) 这种容易误会的代码。

5.5 本章代码规范提示

  • 条件要可读，复杂条件加括号。
  • = 是赋值，== 是判断相等。
  • 不要写数学式链式比较，例如 0 <= score <= 100。
  • 浮点数不要直接用 == 比较。
  • 分支嵌套尽量不超过 2 到 3 层。
  • 可以用提前返回减少嵌套。
  • if、else、else if 即使只有一条语句，也建议加花括号。
  • switch 的每个 case 通常要写 break;。
  • switch 通常要写 default。
  • case 后面必须是常量，不能是变量。
  • 不要在 switch 中使用浮点数或字符串作为判断值。
  • 边界条件要认真测试，例如 59、60、89、90。

5.7 总结与自测

一句话总结

if 系列适合范围和复杂条件，switch 适合判断固定值；写分支时要保证条件可读、边界正确、嵌套不要太深，并记得给 switch 写 break 和 default。
