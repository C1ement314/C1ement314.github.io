7.1.1 你其实早就在用函数了

回头看看前面的章节，你早就和函数打过交道了：

  • int main(void) 就是一个函数定义，它是常规 C 程序的入口；
  • printf("你好\n"); 是一次函数调用；
  • scanf("%d", &age); 也是一次函数调用。

也就是说，函数不是突然冒出来的新东西，而是你已经用了好几章的老朋友。

把它们放在一起对比一下：

函数 谁定义的 是否需要自己写函数体 常见作用 返回值
main 我们自己在源文件中定义 需要 程序入口 int，通常返回 0 表示正常结束
printf C 标准库实现者 不需要 格式化输出 成功时返回写出的字符数量，失败时返回负值
scanf C 标准库实现者 不需要 格式化输入 返回成功赋值的输入项数量，失败时可能返回 EOF
min_int / max_int 我们自己定义 需要 求较小值 / 较大值 返回较小的值 / 较大的值

这张表里有两个重要区别：

  1. main 是我们自己写的函数，但它的调用方式很特殊，通常由运行环境调用；
  2. printf、scanf 是标准库函数，我们只写“调用”，不写它们的“定义”。它们的声明通常放在 <stdio.h> 中，实现在标准库里。

7.3.3 作用域与生命周期

块作用域

一对花括号 { } 形成一个块。块里面声明的变量通常只在块内有效。

函数作用域

函数的参数和函数体内部声明的变量，都属于这个函数。

文件作用域

在所有函数外面声明的变量，具有文件作用域，通常称为全局变量。

全局变量在整个文件中通常都可以访问，但本教程建议：

初学阶段，尽量少用全局变量。

因为全局变量会让函数之间的关系变得隐蔽，程序变大后很难维护。

生命周期

  • 局部变量通常是自动存储期：进入函数时创建，离开函数时销毁；
  • 全局变量和 static 变量具有静态存储期：程序开始时创建，程序结束时销毁；
  • 局部变量如果没有初始化，值是不确定的；
  • 全局变量和 static 变量如果没有显式初始化，会被初始化为 0。

static 局部变量

在局部变量前加 static，可以让它在函数调用之间保持值。

7.3.4 声明与定义的区别

声明和定义很容易混，咱们用一个表区分：

名称 作用 有没有函数体 例子
声明 告诉编译器函数长什么样 没有 int add(int a, int b);
定义 真正实现函数 有 int add(int a, int b) { return a + b; }

一个函数可以声明多次，但通常只能定义一次。

把几个老朋友放在一起看：

函数 声明在哪里 定义在哪里 我们是否需要写定义

main、printf、scanf、min_int 看起来都是函数调用，但来源不同：

  • main 是我们自己写的入口函数；
  • printf、scanf 是标准库提供的函数；
  • min_int、max_int 是我们自己写的普通函数。

如果同一个函数被定义了两次，链接时可能报“重复定义”错误。

以后学到多文件编程时，通常会把函数声明放在头文件 .h 中，把函数定义放在源文件 .c 中。这个会在第 16 章详细讲。

递归和循环怎么选？

对比项 递归 循环
可读性 对树、分治等问题很自然 对重复计算很直接
内存 每层调用占栈帧 通常只占固定局部变量
风险 太深会栈溢出 写错条件会死循环
性能 函数调用有开销 通常更省
建议 适合问题天然递归时 能简单循环就循环

初学阶段，能用循环清楚解决的问题，优先用循环。

  1. 没有基准情况；

7.3.6 函数设计原则

一个好的函数通常满足：

  1. 单一职责

    • 一个函数只做一件事；
    • 不要让一个函数既读输入、又计算、又打印、又写文件。

  2. 名字清楚

    • 函数名用动词；
    • 名字能说明函数做了什么。

  3. 参数不要太多

    • 参数太多，说明这个函数可能承担了太多职责；
    • 可以考虑拆分成多个函数。

  4. 返回值明确

    • 计算型函数返回计算结果；
    • 操作型函数可以返回 void；
    • 如果可能失败，可以考虑返回状态值。

  5. 减少副作用

    • 尽量不要偷偷修改全局变量；
    • 尽量通过参数传入数据，通过返回值传出结果。

  6. 函数不要太长

    • 太长通常意味着职责不够单一；
    • 可以拆成几个小函数，再由主函数调用。

函数接口设计练习

先写函数声明，再写函数定义：

  1. int read_score(void); 读取一个 0 到 100 的成绩，失败时返回 -1；
  2. int is_pass(int score); 判断是否及格，返回 1 或 0；
  3. double average(int total, int count); 计算平均分，人数为 0 时返回 0.0；
  4. char grade_of(double average); 返回等级字符；
  5. void print_result(int count, int total, double average, char grade); 打印结果。

7.3.7 再谈 main、printf、scanf 和 min/max

既然你已经会用函数了，咱们再从函数视角看一遍那几个老朋友。

main

  • main 是一个函数；
  • 我们负责写它的函数体；
  • 它通常由程序启动代码调用；
  • 返回值通常交给操作系统；
  • 返回 0 通常表示正常结束。

printf

  • printf 是标准库函数；
  • 声明在 <stdio.h> 中；
  • 定义不在我们的源文件里；
  • 它接收格式串和后面的参数；
  • 返回成功写出的字符数量，失败时返回负值。

scanf

  • scanf 也是标准库函数；
  • 声明在 <stdio.h> 中；
  • 它需要变量的地址，所以常写 &age；
  • &age 是传给函数的实参，不是函数名的一部分；
  • 它返回成功赋值的输入项数量，失败时可能返回 EOF。

min_int 和 max_int

  • 它们是我们自己定义的函数；
  • 不需要包含特殊头文件；
  • 定义和声明都由我们负责；
  • C 标准库没有现成的 min、max 函数。

7.3.8 本章代码规范：单一职责，函数名用动词

这一章最重要的两条规范是：

  1. 单一职责

    • 推荐：read_score() 只负责读成绩；
    • 不推荐：read_and_check_and_print_score() 什么都干。

  2. 函数名用动词

    • 推荐：print_menu()、calculate_average()、is_pass()；
    • 不推荐：menu()、average()、pass() 这种含义不够明确的写法。

其他小习惯：

  • 函数定义前先想清楚参数和返回值；
  • 函数声明放在文件开头，或者放在头文件里；
  • 函数体保持统一缩进；
  • 不要滥用全局变量；
  • 递归一定要有基准情况；
  • 复杂功能拆成多个小函数。

7.5 本章代码规范提示

  • 函数尽量单一职责，一个函数只做一件事。
  • 函数名用动词，尽量见名知意。
  • 函数定义前先想清楚参数和返回值。
  • 函数声明和定义的返回类型、参数类型必须一致。
  • 非 void 函数必须有返回值。
  • 不要滥用全局变量。
  • 局部变量使用前要初始化。
  • 值传递不会修改调用者的变量。
  • 递归必须有基准情况，并确保每次都在靠近基准情况。
  • 递归太深可能导致栈溢出。
  • 函数太长时，考虑拆分成更小的函数。
  • 复杂功能可以由多个小函数组合完成。

7.6 常见错误

错误 1：函数定义在调用之后，却没有声明

解决方法：在 main 前面加函数声明：

错误 2：声明和定义不一致

这会导致编译错误或链接错误。声明和定义必须匹配。

错误 3：非 void 函数忘记返回值

非 void 函数必须返回一个值。

错误 4：void 函数却使用返回值

错误 5：函数名写错或大小写写错

C 语言区分大小写。函数名必须完全一致。

错误 6：参数个数或类型不匹配

调用函数时，参数个数和类型要尽量匹配。类型不匹配时可能发生隐式转换，导致结果不符合预期。

错误 7：修改形参却以为能改变实参

C 语言默认是值传递，修改形参不会改变实参。

错误 8：递归没有基准情况

递归必须有结束条件，否则会一直调用下去，最终可能栈溢出。

错误 9：全局变量滥用

全局变量会让函数的输入和输出变得不明确，程序变大后难以维护。尽量通过参数和返回值传递数据。

错误 10：变量作用域理解错误

局部变量只在它所在的函数或代码块中有效。

7.7 总结与自测

一句话总结

函数把一段代码封装成可重复调用的“小机器”；main、printf、scanf 和你自己写的 min_int、max_int 本质上都是函数，区别在于谁定义、定义在哪里；参数传进去，返回值传出来，函数名用动词，职责要单一。

  4. 值传递。
  5. 不会。函数里修改的是形参这个副本，实参本身不受影响。
  6. 局部变量只在其所在的函数或代码块中有效；全局变量在文件范围内通常都可以访问。

  12. 标准 C 库没有提供通用的 min、max 函数，可以自己写 min_int、max_int 等函数；也可以用宏，但要注意宏可能带来重复求值等问题。
