第 14 章：链表

阅读提示

基础篇先让你会“把节点串起来”。进阶篇会讲增删查改、二级指针、复杂内存管理和错误处理，建议第二遍精读。

我是七平。上一章，动态数组让程序可以按需要扩容。

但数组有一个天然问题：

  • 按顺序存储；
  • 插入和删除元素时，后面的元素都要移动；
  • 扩容时可能要整体复制。

如果数据经常在中间插入或删除，数组就不太方便了。

这一章，咱们学习一种新的数据结构：链表。

链表不需要连续的内存，它用指针把一个个节点串起来。

链表的特点：

对比项 数组 链表
内存布局 连续 不要求连续
随机访问 a[i] 很快 需要从头遍历
中间插入 要移动元素 改指针即可
中间删除 要移动元素 改指针即可
扩容 可能整体复制 申请新节点即可
额外空间 较少 每个节点存指针

一句话：

数组适合“查得多”，链表适合“改得多”。

命名建议：

  • head：头指针；
  • current 或 cur：当前节点；
  • previous 或 prev：前一个节点；
  • next：下一个节点；
  • node：新节点。

其他建议：

  • 每个 malloc 都检查返回值；
  • 遍历时不要修改头指针；
  • 释放前保存 next；
  • 删除头节点注意修改 head；
  • 删除后及时 free；
  • 退出前释放整条链表；
  • 链表操作和输入输出尽量分成不同函数；
  • 复杂操作先画图，再写代码。

  • 链表操作先画图，再写代码。

  • 遍历链表用 p = p->next，不要用 p++。
  • 释放链表前先保存下一个节点。
  • 删除头节点时要修改头指针。
  • 删除节点后不要再访问该节点。
  • 插入节点时注意 next 的指向顺序。
  • 退出前必须释放整条链表。
  • 头指针可能改变的函数，使用 StudentNode ** 或返回新头指针。
  • 只读遍历时使用 const StudentNode *。
  • 输入、输出、链表操作尽量拆成不同函数。

14.7 总结与自测

一句话总结

链表由一个个节点组成，每个节点保存数据和下一个节点的地址；头指针表示起点；遍历用 p = p->next，插入和删除只需修改指针；头指针可能改变时使用二级指针或返回新头指针；退出前一定要释放整条链表。
