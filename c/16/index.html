16.1 先导：为什么要拆文件？

先看一个单文件程序的结构：

代码一多，这个文件会变得很长。

多文件编程的思路是：按职责拆分。

好处：

  • 一个文件只负责一部分功能；
  • 头文件描述“接口”；
  • 源文件负责“实现”；
  • 修改一个模块，通常不用动其他模块；
  • 多人可以同时开发不同模块；
  • 编译时可以只重新编译改过的文件。

一句话：

头文件告诉别人“我能做什么”，源文件负责“我怎么做”。

4. CMake 是拿来干什么的？

CMake 不是编译器，它自己不会把 .c 编译成可执行文件。

CMake 做的是：

  1. 读取 CMakeLists.txt；
  2. 根据项目描述生成构建文件；
  3. 让 Make、Ninja、Visual Studio、Xcode 等工具去完成真正的编译和链接。

对 CLion 用户来说，CMake 尤其重要：

  • CLion 默认使用 CMake；
  • 打开项目时，CLion 会读取 CMakeLists.txt；
  • 添加源文件、头文件目录、编译选项，通常都要改 CMake 配置。

16.2.3 头文件里通常写什么？

头文件通常放：

  1. 函数声明；
  2. 类型定义，例如 struct、typedef、enum；
  3. 宏定义；
  4. 常量的声明；
  5. 其他头文件的包含。

头文件里通常不写：

  • 普通函数的完整定义；
  • 普通全局变量的定义；
  • 大段实现逻辑。

原因：

  • 头文件会被多个 .c 文件包含；
  • 如果里面写了函数定义或变量定义，可能导致重复定义错误。

16.2.4 源文件里通常写什么？

源文件通常放：

  1. 函数定义；
  2. 全局变量定义；
  3. 只在本文件使用的辅助函数；
  4. 具体实现逻辑。

16.3.2 static

static 用在不同的位置，含义不同。

1. static 局部变量

特点：

  • 只在第一次调用时初始化；
  • 函数返回后仍然保留值；
  • 作用域仍然在函数内部。

2. static 全局变量

特点：

  • 只在当前 .c 文件内可见；
  • 其他文件无法访问；
  • 避免命名冲突。

3. static 函数

特点：

  • 只在当前 .c 文件内可见；
  • 适合只在本文件使用的辅助函数；
  • 不会和其他文件中的同名函数冲突。

在项目里，不打算暴露给外部的函数，建议加 static。

16.3.8 本章代码规范：接口与实现分离，头文件保持简洁

这一章最重要的两条规范是：

  1. 接口与实现分离

    • .h 描述别人可以调用的接口；
    • .c 写具体实现；
    • 不要让头文件暴露内部细节。

  2. 头文件保持简洁

    • 只放声明、类型、宏；
    • 不要放普通函数定义和变量定义；
    • 使用头文件保护；
    • 只在需要时包含其他头文件。

其他建议：

  • 项目头文件用双引号包含；
  • 标准库头文件用尖括号包含；
  • 不包含 .c 文件；
  • 只在本文件使用的函数加 static；
  • 全局变量尽量少用，必要时用 extern；
  • 宏参数和整体都要加括号；
  • 复杂逻辑优先用函数，少用宏；
  • 多文件项目用 CMake 或 Makefile 管理构建。

16.7 总结与自测

  5. static 函数只在当前源文件可见；static 全局变量只在当前源文件可见。
  6. 声明变量或函数在别处定义，让其他文件可以访问。
  7. 宏是预处理阶段的文本替换，没有类型检查；函数在编译和运行时处理，有类型检查。
  8. 防止运算符优先级导致展开结果错误。
  9. 调试、平台适配、功能开关、头文件保护等。
  10. 描述如何构建项目，告诉 CMake 源文件、头文件目录和可执行文件。
  11. 因为链接器需要把所有用到的目标文件链接在一起。
  12. 因为 .c 文件包含实现，直接包含可能导致重复定义和编译混乱。
