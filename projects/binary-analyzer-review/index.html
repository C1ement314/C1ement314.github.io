作者：七平

语言：C

涉及知识点：二进制文件 I/O、fopen/fread/fclose、魔数识别、格式化输出、ASCII 可打印字符判断

一、项目背景

这个项目的目标是写一个类似 hexdump 的小工具：

  • 以二进制模式打开任意文件；
  • 读取文件头部数据；
  • 按“偏移地址 + 十六进制 + ASCII”的格式打印；
  • 根据文件开头的魔数，判断常见文件类型。

它很适合练习 C 语言的文件操作和字节级处理。

六、关键点讲解

1. 为什么要用 rb

rb 表示二进制只读模式。

如果用文本模式，某些平台可能会对换行符或特殊字节做转换。二进制模式可以保证读到的字节和文件内容一致。

2. fread 的返回值

fread 返回实际读取到的元素个数。

这里每个元素大小是 1 字节，所以返回值就是实际读取的字节数。

必须使用 size，不能假设文件一定有 64 字节。

3. 为什么魔数判断要检查长度

如果文件只有 1 字节，访问 buffer[1] 就会越界或读取未初始化内容。

所以要先检查 size >= 2 或 size >= 4。

4. 十六进制输出

  • %02X：输出两位大写十六进制；
  • 不足两位时前面补 0；
  • 每个字节后面加一个空格，方便对齐。

八、可以继续改进的方向

  1. 支持读取完整文件，而不是只读前 64 字节；
  2. 支持自定义每行字节数；
  3. 支持更多魔数，例如 PNG、JPEG、ZIP、GZIP；
  4. 把文件类型判断和输出格式拆成更清晰的函数；
  5. 增加错误处理，例如文件读取失败、命令行参数错误；
  6. 支持偏移地址按 32 位或 64 位格式化；
  7. 增加测试文件，验证空文件、小文件、大文件、魔数文件等情况。

九、总结

这个项目偏向底层，把下面这些重要知识点串起来：

  • 二进制文件读取；
  • fread 返回值；
  • 字节数组处理；
  • 魔数识别；
  • 格式化输出；
  • 命令行参数。

最重要的收获是：

处理二进制数据时，不能假设文件长度，也不能随意访问数组范围。

每个字节都应该在确认有效之后再处理。
